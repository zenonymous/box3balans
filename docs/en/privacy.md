# What Box3balans sends

_Nederlands: [privacy.md](../privacy.md)_

Box3balans runs at your place, on your own computer, NAS or home server. There's no account with us, no service in between, no telemetry and no usage statistics. **Amounts, balances and transactions never leave.** What does go out is listed below per feature: mainly the names of what you hold (symbols, ISINs) to fetch prices, and only for what you turn on yourself, the addresses of your wallets and requests to your exchanges.

## How it's arranged

- **A fixed list of destinations.** All hosts Box3balans may connect to are in one file: [`server/src/lib/net.ts`](../../server/src/lib/net.ts). The server only connects to those hosts, only over HTTPS, and only follows a redirect to a host on the list. Every other request is refused and shown in the app. A test fails the build if code is added with a host that's not on the list. **What that does and doesn't cover:** the check is on `fetch`, which Box3balans itself uses to fetch everything, and a lint rule forbids its own code other ways (`node:http`, `node:net` and the like). A dependency that connected outside `fetch` would fall outside it. Only the [sealed-off setup](#running-it-sealed-off) stops that, at network level, and the CI step below would see such a connection.
- **The browser only talks to your own Box3balans.** The app sends a security policy along (Content-Security-Policy with `connect-src 'self'`): the page loads nothing from outside and can't send anything out.
- **See for yourself what was sent.** _Settings → Network_ shows the list, how often each host was contacted per day, the latest requests (without keys) and every refused request.
- **Switch it off yourself.** On the same page you switch connections off per feature, or all of them with _Offline: all off_. What's off, Box3balans refuses just like a host that's not on the list; you then enter prices yourself. A host that serves two features (Bitvavo: prices and your connection) stays reachable as long as one of them is on. The check for new versions has its own switch (_Settings → About_) and is off by default.
- **Checked on every change.** A CI step starts the image of that change in the [sealed-off setup](#running-it-sealed-off), uses it (a user, a stock, a coin, the prices) and fails if there was a connection to a host that's not on the list ([`scripts/check-network.sh`](../../scripts/check-network.sh)).
- **Sharing a format goes through you.** _Help others read this file_ makes a file on your own server with made-up data in the layout of yours. You see what's in it, download it and share it on GitHub yourself; Box3balans doesn't send it ([ADR 0012](adr/0012-formaten-delen-zonder-gegevens.md)).
- **Running it sealed off (optional).** If you don't want to rely on the code, run Box3balans without its own internet access: a proxy only lets through the hosts on the list, and Docker blocks the rest. See [Running it sealed off](#running-it-sealed-off).

| Crypto prices                               | On every price refresh, for price history, and when you search an asset | The symbols (or contract addresses) of the coins you hold, and what you search for            | `api.bitvavo.com`, `api.coingecko.com`, `api.binance.com`                                                                                                                                                                                                                                                                                                                    |
| Balances and transactions of your wallets   | Only for wallets you add, on every sync                                 | The addresses or public keys (xpub) you add; never a private key                              | `mempool.space`, `litecoinspace.org`, `api.blockcypher.com`, `api.koios.rest`, `eth.blockscout.com`, `arbitrum.blockscout.com`, `base.blockscout.com`, `polygon.blockscout.com`, `unichain.blockscout.com`, `soneium.blockscout.com`, `explorer.optimism.io`, `explorer.inkonchain.com`, `rpc.ankr.com`, `api.mainnet-beta.solana.com`, `api.trongrid.io`, `xrplcluster.com` |

| Checking for new versions                   | Only if you turn it on (_Settings → About_)                             | Nothing about you: only which project                                                         | `api.github.com`                                                                                                                                                                                                                                                                                                                                                             |

A new installation without assets only contacts the first two: the precious-metal prices and the exchange rates. If you set up your own Solana server with `SOLANA_RPC_URL`, it's added to the list for wallets.

**What an outsider can infer.** A price source sees from your internet address which assets are requested, not how much of them you have. A block explorer sees which addresses you request; those are already public on the blockchain, the link with your internet address isn't. With an xpub it also sees which addresses belong together, and so the balance and history of that whole wallet. If you want to shield that too, let Box3balans go out through a VPN.

**Your own Bitcoin server.** If you run your own mempool or Electrs server (for example on an Umbrel or Start9), set `MEMPOOL_URL` to the address of its API, such as `http://192.168.1.10:3006/api`. Bitcoin wallets are then requested there and not at mempool.space, so nothing about your Bitcoin wallets leaves your network. On your own network (a private address such as 192.168.x.x or 10.x.x.x, Tailscale's 100.64.x.x, or a local name such as `umbrel.local`) that may simply be http on a port of its own; elsewhere only https. Only that one address gets the exception, and it's on the list for wallets under _Settings → Network_. In the [sealed-off setup](#running-it-sealed-off) the app has no route to your home network; this doesn't work there.

## Checking it yourself

- **In the app:** _Settings → Network_.
- **In the code:** the list in [`server/src/lib/net.ts`](../../server/src/lib/net.ts), and [`test/net.test.ts`](../../server/test/net.test.ts), which guards the list.
- **With your own firewall:** for example [LuLu](https://objective-see.org/products/lulu.html) (free, macOS), Little Snitch (macOS), [OpenSnitch](https://github.com/evilsocket/opensnitch) (Linux) or your NAS's firewall. You'll only see the hosts above.
- **The image:** the images are built by GitHub from this source code and are signed; see [SECURITY.md](../../SECURITY.md#verifying-images).
- **Independently assessed:** the [OpenSSF Scorecard](https://scorecard.dev/viewer/?uri=github.com/zenonymous/box3balans) automatically checks every week how the project is secured (pinned dependencies, signed releases, workflows and more).

## Running it sealed off

Optional, for those who want it enforced at network level. With the files in [`deploy/egress`](../../deploy/egress), Box3balans and its database run on a Docker network with no route out. A proxy ([Squid](https://www.squid-cache.org/), maintained by Canonical) sits in between: it lets your browser in, and only lets Box3balans out to the hosts in `allowed-hosts.txt`, over HTTPS. Docker blocks every other connection, whatever Box3balans's code might try.

1. Put [`docker-compose.yml`](../../deploy/egress/docker-compose.yml), [`squid.conf`](../../deploy/egress/squid.conf) and [`allowed-hosts.txt`](../../deploy/egress/allowed-hosts.txt) together in a folder (instead of the normal `docker-compose.yml`).
2. Start as always: `docker compose up -d`. Box3balans is reachable on the same port (8080).
3. `docker compose logs proxy` shows every connection the proxy let through or refused.

If you don't want a feature, remove its hosts from `allowed-hosts.txt` and restart the proxy (`docker compose restart proxy`): Box3balans can then no longer reach them. Add your own `SOLANA_RPC_URL` yourself. The list belongs to a version of Box3balans: update it when you update, because a new price source or connection needs a new host.
